# 1.1.0 AnyTLS 生命周期补充修复

基线：Laosixok/V2BX-malio `8b8c41c`（1.0.9）。本文记录本次验证；`anytls-memory-fix.md` 中旧版本的结果不代表本次执行。

## 已确认的问题

1.0.9 已包含本地 AnyTLS 入站补丁；它没有使用 replace 模块内原始 AnyTLS 入站。实际依赖为：

- `github.com/sagernet/sing-box v1.12.0` 经 replace 使用 `github.com/wyx2685/sing-box_mod v1.12.0-beta.17.2`。
- `github.com/anytls/sing-anytls v0.0.13`，不是旧的 v0.0.9 伪版本。

检查锁定模块的 `session/session.go`：`recvLoop` 读取 PSH 帧后，在同步 `stream.pipeW.Write(buffer)` 中等待下游消费；缓冲归还发生在该调用之后。`internal/pipe/io_pipe.go` 没有内部队列，写入会阻塞到读端消费或关闭。旧入站 Close/DelUsers 仅关闭 TCP，再等待连接处理函数退出。当路由/下游停止读取 stream 时，关闭 TCP 不会关闭 pipe，接收循环无法退出，Session、goroutine 和当前帧缓冲继续被引用，节点删除也会阻塞。正常 TCP EOF 同样需要接收循环有机会继续读取才能被发现。

依据：[锁定的接收循环和 Close 实现](https://github.com/anytls/sing-anytls/blob/v0.0.13/session/session.go)、[同步 pipe 实现](https://github.com/anytls/sing-anytls/blob/v0.0.13/internal/pipe/io_pipe.go)。

另一个遗漏是上层上下文取消没有中断普通认证读取或正在工作的 Session，半途认证连接可继续保留。

这些是可复现的资源释放缺陷，不足以证明它们解释了约 49 小时 RSS 819MB / 匿名内存 741MB 的全部增长。没有生产堆快照，也未进行 49 小时负载复测。

## 最小修改

- `core/sing/anytls/inbound.go`：每条连接记录 cancel；关闭节点/删除用户时先取消连接工作，再关闭 socket。上下文取消通过 `context.AfterFunc` 关闭原始 socket 和 Session，唤醒认证读取、stream pipe 及接收循环。正常结束时移除回调，不增加每条连接常驻的等待 goroutine。
- `core/sing/anytls/inbound_test.go`：增加 unread stream 的 Close/DelUsers/上下文取消回归，以及连续半途认证取消。检查处理函数退出、回调恰好一次、连接注册表归零及路由上下文取消。
- `VERSION`：1.1.0。构建仍通过 build.sh 的 ldflags 写入运行版本。
- `go.mod`：tidy 将已有直接导入的 sing-shadowsocks 移除 indirect 标记，未改变版本或校验和。
- `docs/anytls-memory-fix.md`：增加本次增量说明入口，保留历史测试记录。

不升级共享 sing-box_mod/sing 依赖，也不修改 SSPanel/Malio API、配置格式、VLESS、Hysteria2 或其他协议处理逻辑。已有用户更新锁、幂等添加、认证身份归属和 TLS 异常退出清理继续保留；现有注册/32 次 reload、用户更新、流量缓存及面板回归继续参与验证。

执行环境：macOS amd64，官方 Go 1.24.1（安装包 SHA256 已校验）。除竞态测试外使用 `CGO_ENABLED=0`，与 Linux 发布构建一致。

## 部署与回滚

仅在验证通过并经过审查后部署。先选一台 Linux 节点，备份实际运行核心、配置和服务设置，记录旧版本与哈希。`build.sh` 生成 amd64/arm64 两个带完整协议标签的发布包；按服务器架构选择，校验 SHA256SUMS。此次不需要改配置或更换规则数据库。

用 `systemctl show V2bX --property MainPID --value` 找到 PID，再用 `/proc/<PID>/exe` 确认实际核心路径；不要覆盖可能为管理脚本的 `/usr/bin/V2bX`。停止服务后替换核心并启动，核对版本 1.1.0、日志、面板用户同步及 AnyTLS/VLESS/Hysteria2 实际连接。升级会断开已有连接。

若启动或协议回归异常，停止服务、恢复备份的旧核心与原服务设置后启动。不要把重新运行 latest 安装脚本当作版本回滚。

部署前后使用 `scripts/observe-memory.sh` 记录相近负载下的 RSS、匿名内存、FD、TCP、PID，至少覆盖 49 小时；记录用户更新和节点重载时间。PID 改变需分段比较。结合 GC 后存活堆或受限访问的 heap/goroutine profile 判断是否仍有持续保留；RSS 不立即下降不等于存活堆仍增长。本次没有添加公开诊断端口。
